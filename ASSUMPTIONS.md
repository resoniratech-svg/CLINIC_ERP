# ASSUMPTIONS & TECHNICAL ARCHITECTURE DESIGN

## 1. Single Branch UI vs Database Architecture
- **Assumption**: The UI strictly exposes operations for a single hospital branch (`Hyderabad Main Branch`, `HYD001`). No API endpoint exists for "Create Branch" or "Add Branch".
- **Database Design**: Every operational table (`users`, `doctors`, `executives`, `patients`, `leads`, `appointments`, `bills`, `payments`, `cash_ledger`, `expenditures`, `cash_deposits`, `crm_followups`, `medicine_stock`, `audit_logs`, `targets`) includes `branch_id INTEGER NOT NULL DEFAULT 1 REFERENCES branches(branch_id)` to enable seamless multi-branch scaling in future schema migrations.

## 2. Authentication & Password Security
- **Authentication**: Stateless JWT-based authentication (`expiresIn: 24h`). Passwords are never stored or returned in plaintext anywhere, including to Super Admin.
- **Forgot Password Workflow**: When a user submits a forgot-password request, an entry is created in `password_reset_requests` with status `pending`. Super Admin views the queue and approves the request. System generates a 10-character temporary password, hashes it into the user's `password_hash`, sets `must_change_password = true`, and returns the temporary password ONCE to Super Admin for distribution.

## 3. Doctor Resignation & Responsibilities Transfer
- **Rule**: Deactivating or marking a doctor inactive (resignation) NEVER deletes their historical record or reassigns their past clinical notes/diagnoses/prescriptions.
- **Transfer Endpoint**: `POST /api/v1/doctors/:id/transfer` accepts `to_doctor_id` (must be an active doctor). Reassigns ONLY forward-looking active responsibilities (future appointments with `appointment_date >= CURRENT_DATE`, pending renewals, pending followups). Historical clinical records permanently remain linked to the original doctor ID.

## 4. Split Billing Responsibilities
- **Receptionist Billing**: Restricted exclusively to `bill_type = 'consultation'`. Requests for `treatment` or `other` bill types by a Receptionist are rejected with HTTP 403.
- **PRO/Manager Billing**: Authorized to create `treatment` and `other` bills, record payments, manage discounts, and collect dues.

## 5. Payment Methods & Cash Ledger Mechanics
- **Payment Methods**: Exactly 5 methods are supported (`cash`, `card`, `upi`, `razorpay`, `bajaj_pay`), configurable active/inactive by Super Admin.
- **Grand Total Revenue**: Computed as `Cash + Card + UPI + Razorpay + Bajaj Pay`.
- **Cash Ledger**: Strict Cash-only accounting. Non-cash payments (`card`, `upi`, `razorpay`, `bajaj_pay`) do NOT touch `cash_ledger`. Closing cash balance formula (`Closing = Opening + Cash Revenue - Cash Expenditure - Cash Deposit`) is enforced server-side.

## 6. Target Management & Walk-in Auto-Classification
- **Validation**: Enforces `Enquiry Target + Unit Target = Overall Target` on save unless `allow_unallocated = true`.
- **Walk-in Classification**: When checking or registering a patient by mobile number, existing mobile -> `patient_type = 'existing'` (revenue routes to `Unit Target`); new mobile -> `patient_type = 'new'` (revenue routes to `Enquiry Target`).
- **Unit Target Inclusions**: Renewals, Employee Referrals, Patient Referrals, and Due Collections automatically contribute to Unit Target.

## 7. Executive Call Center & Incentives
- **Leads Queue**: Leads generated by Call Center Executives (inbound/outbound) land in the Receptionist queue with `status = 'new'` for doctor assignment.
- **Incentive Calculation**: `incentive_earned = leads_generated * per_lead_incentive`.
- **Outbound Import**: Validates duplicate mobile numbers across patients and leads before inserting.

## 8. Audit Logging & Login Logs
- **Audit Middleware**: Mutating HTTP requests (POST, PUT, PATCH, DELETE) automatically write a structured record to `audit_logs` capturing user, role, action, module, record ID, old value, new value, IP address, device, browser, and branch ID.
- **Login Logs**: Authentication attempts write to `login_logs`. Logouts record the exact session duration in seconds (`session_duration_seconds`).
